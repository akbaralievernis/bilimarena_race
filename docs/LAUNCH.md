# Запуск Bilim Arena Race в классе

Этап 6: всё, что нужно сделать один раз перед первым уроком, и короткий чек-лист перед
каждой гонкой. Шаги с аккаунтами (Supabase, Vercel) делает владелец проекта — приложению
и разработчику пароли и секретный ключ не нужны.

## 1. Supabase — один раз

Dashboard проекта → разделы ниже.

| Где | Что сделать | Зачем |
| --- | --- | --- |
| **Authentication → Rate Limits** | «Anonymous sign-ins» — поднять с 30 до **300 в час** | В школе все телефоны выходят в интернет с **одного IP**. При 30 в час 31-й ученик не войдёт. Ученик входит прямо из браузера, поэтому лимит считается по IP школы |
| **Authentication → Sign In / Providers** | Anonymous Sign-Ins — **включены** | Ученики входят без регистрации |
| **Authentication → URL Configuration** | Site URL: `https://<ваш-домен>`; Redirect URLs: `https://<ваш-домен>/**` | Ссылка из письма подтверждения ведёт на сайт, а не на localhost |
| **SQL Editor** | Миграции этапов 1–5 применены (проверяет `/status`) | Без них сайт пишет «база не настроена» |
| **Settings → General** | Запомните **Region** проекта | Понадобится для Vercel (шаг 2) |

Бесплатный тариф Supabase **усыпляет проект после 7 дней без запросов**. После деплоя
Vercel раз в сутки сам открывает `/api/health` (см. `vercel.json`), и проект не засыпает.
Если всё же уснул — Dashboard → **Restore project** (1–2 минуты).

Лимиты бесплатного тарифа с запасом покрывают класс: до 200 одновременных подключений
Realtime (класс из 40 учеников — 41 подключение), 100 сообщений в секунду.

## 2. Vercel — один раз

1. [vercel.com](https://vercel.com) → войдите через GitHub → **Add New → Project** →
   импортируйте `akbaralievernis/bilimarena_race`. Next.js определится сам.
2. **Environment Variables** (Production и Preview):
   - `NEXT_PUBLIC_SUPABASE_URL` = `https://wiempvgkqlgfgtwpqgdc.supabase.co`
   - `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` = публичный ключ `sb_publishable_…`
     (тот же, что в `.env.local`). **Секретный ключ `sb_secret_…` не добавляйте никогда.**
3. **Deploy**. Регион функций задан в `vercel.json` (`"regions"`) рядом с регионом
   Supabase: у рабочего проекта это Seoul `ap-northeast-2` → **`icn1`**. Для другого
   проекта Supabase поменяйте его (Frankfurt `eu-central-1` → `fra1`, Singapore → `sin1`,
   Mumbai → `bom1`). Каждая страница делает 1–3 запроса к базе; если сервер и база на разных
   континентах, это +0,3–0,5 с к каждой странице.
4. Впишите адрес из Vercel (`https://….vercel.app`) в Supabase → URL Configuration (шаг 1).
5. Откройте `https://<домен>/status` — все пункты должны быть зелёными.

После изменения переменных окружения нужен **Redeploy** — `NEXT_PUBLIC_*` встраиваются
в сборку.

## 3. Перед каждой гонкой (5 минут)

1. На компьютере у доски откройте **`/status`** → «Всё готово к гонке».
2. Откройте `/status` на **одном телефоне ученика в школьном Wi-Fi**. Если «WebSocket
   заблокирован» — гонка всё равно работает, но карта обновляется раз в 10 секунд, а не
   мгновенно; если «Нет связи с сервером» — сеть школы блокирует `*.supabase.co`, используйте
   мобильный интернет.
3. Создайте гонку заранее (`/create`), проверьте задания. Код комнаты появится в лобби.
4. Экран лобби — на проектор: код крупно виден всем.
5. Ученики открывают сайт → «Подключиться» → код → имя. Учитель раскладывает их по
   командам (лучше 3–5 человек в команде).
6. «Начать гонку». Учителю удобно держать на проекторе экран гонки (карта и места), а
   управление — с ноутбука.

## 4. Во время гонки

- **Телефон потерял связь** — ничего страшного: при возвращении экран сам догрузит
  состояние. Ответы и позиции хранятся на сервере, не в телефоне.
- **Ученик закрыл вкладку** — открыть сайт снова: сессия сохранена в браузере, он вернётся
  в свою команду. Если открыл в другом браузере — подключится заново по коду как новый
  участник; учитель переносит его в команду.
- **Неверный ответ** — команда ждёт 10 секунд (так задумано: перебор вариантов не работает).
- **Карта не обновляется мгновенно** — во время гонки она в любом случае перечитывается
  каждые 20–25 секунд; при потере Realtime — каждые 10 секунд.
- **Завершить гонку** может только учитель; после этого ответы не принимаются, у всех
  появляются итоги, у учителя — «Отчёт».

## 5. Если что-то пошло не так

| Симптом | Причина | Что делать |
| --- | --- | --- |
| «Слишком много попыток» при подключении ученика | Лимит анонимных входов с одного IP | Поднять лимит (шаг 1); пока — мобильный интернет для оставшихся |
| Сайт открывается, но «Не удалось загрузить гонку» у всех | Проект Supabase уснул или недоступен | `/status`; Dashboard → Restore project |
| «База данных гонки не настроена» | Не применена миграция | `/status` покажет, какого этапа; SQL Editor |
| Письмо подтверждения ведёт на localhost | Не задан Site URL | Шаг 1, URL Configuration |
| У одного ученика всё «зависло» | Старая вкладка, сон телефона | Обновить страницу |

## 6. Нагрузочный тест

`npm run test:load` проводит настоящую гонку против проекта из `.env.local`: учитель из
`.env.test.local` и N анонимных учеников. Каждый «телефон» ведёт себя как приложение:
слушает Realtime-канал, перечитывает `get_lobby()` по сигналу и раз в 20–25 секунд,
думает 2–7 секунд и отвечает (30 % ответов неверные).

```bash
npm run test:load
```

```bash
LOAD_STUDENTS=60 LOAD_TEAMS=10 npm run test:load
```

Тест печатает время входа, подключения, `get_lobby`, `submit_answer`, через сколько ход
команды виден на других телефонах, и проверяет, что ошибок нет, а отчёт учителя насчитал
ровно столько ответов, сколько принял сервер. Каждый ученик — новый анонимный
пользователь, поэтому **сначала поднимите лимит анонимных входов** (шаг 1).

Выводы:

- Класс из 30–60 человек база и Realtime выдерживают с запасом: ни одной ошибки, ход
  команды появляется у всех меньше чем за секунду, отчёт сходится с принятыми ответами.
- Нагрузка растёт как «число устройств × частота ответов»: каждый ответ заставляет все
  телефоны перечитать лобби. При 60 учениках это ~50 чтений в секунду, медиана почти не
  изменилась. Для нескольких классов одновременно (150+ устройств) стоит повторить тест.
- Реальная школьная сеть медленнее, чем здесь: проверяйте её через `/status` на телефоне
  ученика (раздел 3).
