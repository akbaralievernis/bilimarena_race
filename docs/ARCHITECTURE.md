# Архитектура Bilim Arena Race

Документ фиксирует принципы, на которых строится игра. Схема данных — черновик:
она будет уточнена и реализована миграциями на Этапе 1 вместе с первой игровой механикой.

## Участники

| Роль | Как входит | Что видит и делает |
| --- | --- | --- |
| Учитель | Аккаунт Supabase Auth (email / OAuth) | Создаёт гонку, настраивает маршрут, запускает и останавливает её |
| Студент | Анонимная сессия Supabase Auth — без регистрации, но с JWT, по которому RLS понимает, кто это | Входит по коду комнаты, выбирает команду, проходит испытания |
| Общий экран | Страница учителя в режиме «только чтение» | Карта гонки и положение команд в реальном времени |

## Модель доверия

**Браузер отправляет только намерения, итог решает сервер.**
Клиент может сказать «команда отвечает X на задание Y», но не может сказать «у нас +50 очков».

Решает только сервер:

- правильность ответа и число очков;
- перемещение команды по карте;
- время (единственный источник — `now()` в Postgres, а не часы устройства);
- завершение гонки, победителя и награды;
- применение бонусов.

Как это обеспечивается:

1. **RLS на каждой таблице.** Клиентам по умолчанию разрешено только чтение того,
   что им положено видеть. Прямые `insert` / `update` в игровые таблицы закрыты.
2. **Изменения — только через доверенный код:**
   - Postgres-функции (`security definer`, фиксированный `search_path`), вызываемые через RPC.
     Функция сама проверяет, что пользователь состоит в команде, гонка идёт, задание открыто,
     и атомарно записывает результат. Основной путь для игровых действий.
   - Next.js Route Handlers / Server Actions (`lib/supabase/server.ts`, пакет `server-only`) —
     для операций, которым нужна логика вне БД (например, будущая проверка кода).
3. **Правильные ответы не покидают сервер.** Эталонные ответы хранятся отдельно от текстов
   заданий, в таблице без клиентского доступа (или в непубличной схеме), и не отдаются
   в браузер до закрытия задания.
4. **Журнал событий.** Каждое игровое действие пишется в append-only таблицу событий:
   это и аудит («почему команда оказалась здесь»), и источник данных для аналитики.

## Realtime

- **Авторитетное состояние** (позиции, очки, статус гонки) рассылается из базы:
  Postgres Changes или Broadcast из триггеров. Клиенты только подписываются.
- **Presence** — только «кто сейчас в комнате»; на счёт и позиции не влияет.
- **Клиентский Broadcast** — только для некритичных эффектов (анимации, реакции).
  Такие сообщения никогда не меняют состояние гонки.

Отдельный игровой WebSocket-сервер пока не нужен: Vercel не держит долгие соединения,
а доставку событий берёт на себя Supabase Realtime. Если понадобится серверный «тик»
(таймеры раундов), варианты — `pg_cron`, Supabase Edge Functions или отдельный воркер.

## Черновик модели данных

| Таблица | Назначение |
| --- | --- |
| `races` | Гонка: учитель, тема, код комнаты, статус (`draft` → `lobby` → `running` → `finished`), время старта и финиша |
| `race_teams` | Команды гонки: название, цвет, текущая позиция, очки (пишет только сервер) |
| `race_members` | Участники: пользователь ↔ команда |
| `route_checkpoints` | Маршрут: порядок чекпоинтов и тип испытания на каждом |
| `challenges` | Тексты заданий (без правильных ответов) |
| `challenge_solutions` | Эталонные ответы — без клиентского доступа |
| `submissions` | Попытки команд и вердикт сервера |
| `race_events` | Append-only журнал событий гонки → аналитика |

## Структура проекта

```text
app/                  маршруты Next.js (App Router)
  page.tsx            стартовая страница
  create/, join/      временные страницы-заглушки
components/           UI-компоненты
  ui/                 базовые элементы (кнопки)
lib/
  env.ts              чтение и проверка переменных окружения
  supabase/client.ts  клиент для браузера (сессия, Realtime, чтение по RLS)
  supabase/server.ts  клиент для сервера (server-only)
supabase/             конфигурация Supabase CLI; здесь появятся миграции
tests/                unit-тесты (Vitest)
docs/                 документация
```

Папки для типов, хуков и игровых модулей появятся вместе с кодом, которому они нужны.
